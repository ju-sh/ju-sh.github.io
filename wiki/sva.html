SystemVerilog Assertions

  • Boolean negation: not p or ! p ??

  • p and q: p and q should be true, but both need not end at same time

  • p intersect q: Concurrent and

    • also p && q ??

  • p ##N q: check if p holds, then check if q holds N cycles later

    • Eg: p ##2 q

  • p [*N]: p is repeated N times

    • Eg: p [*3]

  • Implication:

    • Overlapping (p |-> q)
      • If p is true, then q must hold on the same cycle
    • Non-overlapping (p |=> q)
      • If p is true, then q must hold on the next cycle
      • Equivalent to something like p ##1 (true |-> q)

  • $stable(sig_var): true if sig_var value didn't change

    • ie, it has the same value as it had in the previous clock cycle

  • $changed(sig): opposite of $stable

  • disable iff: disable enforcing a property if a condition is met

    property fifofull;
  @(posedge clk) disable iff(reset)
    fifo_full && wr_en && !rd_en |=>  $stable(fifo_wr_ptr) ;
end property

  • Display a message if assertion failed:

    fifofull_assert: assert property(fifofull) else 
  $display("fifofull assertion failed");
    • Source: https://verificationacademy.com/forums/t/fifo-module-assertion/47471

  • onehot: only one bit is high

  • onehot0: only one bit is low

  • $rose(sig_var): true if sig_var has made a 0 to 1 transition

  • $fell(sig): true if sig made a 1 to 0 transition

  • $countbits(signal, 1): count matching bits

  • sig throughout operation: sig true throughout operation

Temporal operators

  • seventually
  • until

Terms

  • Assertion
  • Assumption
  • Cover point
    • Something that is only occassionally true
    • Kind of like coverage in tests

Examples

  • Request must be followed by grant
    • req |=> grant: grant given on the very next cycle
    • req |=> seventually grant: LTL would be like □(req → ◇grant)
